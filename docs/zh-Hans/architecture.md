# 代码组织

GUI 和 CLI 共用工具预设及宝可梦准备逻辑。各游戏模块保留实测的传输格式和时序；通用组件放在游戏目录之外。

| 位置 | 职责 |
| --- | --- |
| `pokeldn/app/` | 功能目录、参数组装、解析器检查、设置、路径和子进程 |
| `pokeldn/pokemon.py` | PKHeX 服务、导入、最终交换提议验证和接收文件 |
| `pokeldn/gifts.py` | 通用[神秘礼物文件](gifts.md)封装、读取、写入和原生格式转换 |
| `services/pkhex/` | 固定版本的 PKHeX.Core 依赖；合法遭遇生成和游戏兼容性检查 |
| `pokeldn/ldn/` | 无线传输、IP、Pia、可靠性和信道表 |
| `pokeldn/online/` | [在线交换](online.md)：中继、匹配和交换伙伴的加密通道 |
| `pokeldn/gba/` | GBA 无线连接协议 |
| `pokeldn/gen8.py`, `pokeldn/gen9.py` | 通用宝可梦记录编解码 |
| `pokeldn/<game>/` | 游戏标识、消息、状态机和协议差异 |
| `bin/` | 参数解析器和会话编排 |
| `gui/` | 视图、控件、主题和开发板操作 |

FRLG 的配置、通告和礼物设置位于 `pokeldn/frlg/`。旧配置及编解码器导入路径保留少量兼容代码。

应用一次只运行一个会话，因为一块开发板只能供一个进程使用。“停止”仅显示在正在运行会话的工具上；启动另一工具时，先停止当前会话并等待退出，再启动新会话。烧录也会占用开发板，启动会等待烧录完成。

## 宝可梦准备

共享服务生成合法遭遇并以所选游戏的格式保存导入。每个交换启动器在打开其无线收发设备之前都会准备一个提供的文件。编辑和请求的新身份在应用后进行检查。不兼容的格式、不可用的种类和非法的最终记录将被拒绝。会话的训练家身份不会覆盖导入的宝可梦的初训家。

PKHeX的`LegalityAnalysis.Parsed`记录分析是否完成。助手将其返回为
`parsed`。检查 `parsed: false` 会重新启动帮助器并重复相同的请求一次；第二次不完整的分析会引发验证器错误。已完成的拒绝记录的检查仍被拒绝。服务锁涵盖首次检查、重启和重试。

PID 和加密常量的更改可能会使遭遇相关性失效，尤其是事件和袭击。新身份是可选择加入的，并且必须通过 PKHeX；保留固定事件训练家。所提供的合法记录和新身份下的非法记录保持其自己的 PID 和加密不变，并且启动器会记录 `the offer kept its own PID`。一个构建会在该种类的每一次遭遇之后尝试神秘礼物遭遇，因此具有野生、静态或蛋遭遇的种类永远不会被构建为事件。

生成宝可梦就是将一次遭遇转为记录。异色要求传入遭遇条件，因此第三世代 PID 保持 PKHeX 要求的 RNG 关联。单一性别种类也会指定遭遇性别：蜂女王和雪妖女只能由雌性三蜜蜂、雪童子生成。PID、个体值及野生遭遇栏位的等级随机生成，每种遭遇最多尝试八次，再跳过。没有符合直接捕获条件的遭遇时，经进化得到的种类会提升到所需进化等级。进化记录采用进化后种类的无性别状态（如土居忍士进化的脱壳忍者）；原遭遇形态在进化后不存在时使用形态 0（如伽勒尔大葱鸭进化的葱游兵）。

在级别或种类更改后失败的记录会分步修复，每一步都在最后一个之上，并保留第一个合法结果：

1. 只能通过 HOME 进入游戏的活动礼物（《剑／盾》的捷拉奥拉、美录梅塔）补上 HOME 追踪码。这一步先于招式修正，以免替换活动固定招式。
2. 修正招式、回忆招式、招式学习器及招式记录标志、强化招式标志、精通标志，以及《传说 阿尔宙斯》的尺寸。推荐配招可包含只有设置相应学习记录后才合法的招式。
3. 将进化记录的特性更新为进化后种类在原捕获特性槽位上的特性。
4. 没有最近持有人的记录补上第二位训练家 `POKELDN`：连接交换进化意味着已经交换过；部分礼物（如《传说 Z-A》的玛机雅娜）获得时就已有最近持有人。
5. 依赖计数的进化（击中要害次数、受到的伤害、愤怒之拳使用次数、金币）设置所需计数。
6. 《晶灿钻石／明亮珍珠》中达到美丽度阈值的进化（美纳斯，170）设置相应美丽度，以及所需宝芬对应的最低光泽。

先刷新特性、再修正招式会导致《传说 Z-A》的赛富豪不合法，因此执行顺序固定。

PKHeX 无法满足的请求将被拒绝并给出原因。低于最低遭遇级别的级别报告该级别；每次遭遇都被异色锁定的异色请求报告；一个在游戏中没有遭遇过的种类报告了这一点。固定级别的礼物和仅限活动的种类没有较低级别的形式。用六种请求形状（素色、异色、50级、100级、50级异色、昵称）横扫每场游戏的每一个种类，失败的素色构建是：

|游戏 |种类 |失败|
|---|---|---|
| 火红／叶绿 | 386 | 0 |
| Let's Go | 153 | 0 |
| 传说阿尔宙斯 | 226 | 0 |
| 晶灿钻石／明亮珍珠 | 493 | 2 |
| 剑／盾 | 664 | 3 |
| 传说 Z-A | 364 | 5 |
| 朱／紫 | 733 | 32 |

除三种情况外，失败均因 PKHeX 没有该游戏的对应遭遇：《晶灿钻石／明亮珍珠》的时拉比、代欧奇希斯，《剑／盾》的蒂安希、玛机雅娜、美录坦，《传说 Z-A》的粉蝶虫、粉蝶蛹、彩粉蝶、基格尔德，以及《朱／紫》中只能从 HOME 传入的传说的宝可梦。具有遭遇但仍失败的是《传说 Z-A》的美纳斯，以及《朱／紫》的诡角鹿、月月熊。PKHeX 没有诡角鹿、月月熊的第九世代进化；由丑丑鱼生成且带有最近持有人的 Z-A 美纳斯，在 PKHeX 进化链中停于美纳斯，而游戏记录不接受华丽大赛数值。

### 提供选项

生成时还可指定形态、性格、特性、性别、持有物、精灵球、最多四个招式、个体值及努力值。招式和形态将搜索范围缩小到可拥有这些选项的遭遇。性格、特性、性别、个体值作为遭遇条件传入；第三世代会搜索符合所选性格的 PID。遭遇随机结果与请求不同时，按玩家在游戏中可用的方式修改，再由合法性分析判断：

|不同 |改变 |
|---|---|
| 性格 | 第八世代起，用薄荷改变能力值修正所用性格 |
| 特性 | 调整特性槽位（特性胶囊或特性膏药） |
| 要求为 31 的个体值 | 极限训练，要求等级 100（第七、八世代）或 50（第九世代） |
| 形态 | 仅设置玩家可改变形态的种类，如洛托姆的电器形态 |

持有物、精灵球及努力值在生成后设置。第三、四世代中超过 100 的单项努力值，只有宝可梦在获得后取得过经验才合法，因此给记录增加一点经验，同时保持低于下一等级。《传说 阿尔宙斯》的奋斗等级等于存储值加个体值带来的偏移（个体值至少 20 加 1、至少 26 加 2、为 31 加 3）；存储值超过 10 减偏移时不合法，因此将请求视为游戏显示的等级，再减去偏移。

记录必须包含每个请求并通过合法性分析。第一次遇到的情况会被保留，而第一个没有遇到的请求会在拒绝中被提及。

提供的选项是一个种类在该游戏中可以拥有的选项：

| 选项 | 显示条件 |
|---|---|
|球 | PKHeX 允许它至少在该种类的一次遭遇中 |
| 特性 | 存在拥有该特性的合法生成结果；《传说 Z-A》不列出特性 |
|持有物 | PKHeX 将其列为游戏已发布的持有物； Let's Go 和传说阿尔宙斯都没有 |
| 努力数值 | 努力值每项最多 252、合计 510；Let's Go 的觉醒值每项最多 200；《传说 阿尔宙斯》的奋斗等级每项最多 10 |

每款游戏抽取 25 个种类，分别测试所有可选精灵球、各性格、固定个体值、固定努力值、各性别和持有物；8095 次生成中 8088 次合法。PKHeX 拒绝《剑／盾》活动时拉比的勤奋、坦率、害羞性格，以及《传说 Z-A》礼物美录梅塔的这三种性格和浮躁性格。

在零售剑上，使用自定义选项构建的宝可梦并在下一个排队的交易所进行交易，保存了等于提议的记录（[提议记录](swsh_trade.md#the-offered-record)）。在零售晶灿钻石和朱上，异色37级皮卡丘的昵称、性格、隐藏特性、性别、持有物、球、四招、IV和努力值在其摘要屏幕上显示每个选项；晶灿钻石的回售记录在所有十二个领域均匹配。

### Showdown 配置

导入粘贴读取宝可梦 Showdown、Smogon 或 PKHeX 设置与 PKHeX 自己的解析器（`ShowdownParsing.GetShowdownSets`）并填写构建表单；构建然后进行记录。解析器读取 PKHeX 导出的任何语言的集合（英语、法语、德语、意大利语、西班牙语、日语、韩语、中文）； PKHeX 自己的拼写之外的手写标记（例如 `Nature : Rigide` 的 `Nature Rigide`）是它无法读取的行。团队出口
`=== [gen9] Team ===` 标头被跳过。文本遵循 Showdown 的默认值：没有 `Level:` 行意味着级别 100，`IVs:` 行省略的 IV 是 31。解析器按照 PKHeX 的顺序保留统计数据，速度第四。

|集合名称 |结果 |
|---|---|
| 无法解析的行、游戏中不存在的种类或形态、种类没有的特性、游戏中不能持有的道具、不存在的招式、努力值超过 510 | 拒绝并说明原因，不填入任何内容 |
| 太晶属性、超极巨化、极巨化等级、亲密度、觉醒力量属性 | 填入其他内容，忽略这些字段并说明 |
| Let's Go 或《传说 阿尔宙斯》的努力值、《传说 Z-A》的特性 | 忽略并说明 |
|几组，在交换队列中|每个交换按其粘贴到的选择器的顺序填充：重复使用后未触及的选择器，否则插入一个交换，直到队列的限制；不适合的集合计入注释。任何一组的拒绝都拒绝粘贴 |
|几套，在队列外|第一个填写表格，并附上注释 |

剑／盾神秘礼物验证WC8封印并使用PKHeX检查支持的种类、形态、招式和安全物品。定制 WC8 卡是发行版，这种结构检查并不会使它们成为正式事件。可选的 `--image` 研究检查使用用户提供的游戏二进制文件；不需要分发卡。

### Let's Go 链接代码

Let's Go 主机端的连接密码有三个位置。点击位置会打开与游戏主机一致的十只宝可梦选择器，两行、每行五只，图片下方显示名称，因此图片未下载也能辨认；选择后填入当前位置并打开下一个空位。内部值为三个逗号分隔的英文名称，与 `--code` 一致。“开始”会等待三项全部设置：若存在空位，启动器会使用默认密码，游戏主机的搜索无法找到它。

### 交换队列

一个工具，其入口点在一个席位上完成多个交易，最多需要六个宝可梦； “添加交换”添加一个选择器，会话按顺序提供它们，每个已完成的交换一个。选择器成为重复的提议标志：

| 工具 | 提供的宝可梦 | 最后一次交换之后 |
|---|---|---|
| 火红／叶绿主机并加入| 队伍文件，`--trades N`，插槽 0 至 N-1 |主机拒绝进一步交换（`PLAYER_CANCEL_TRADE`）并等待玩家的“取消”和“是”；方加入取消离开|
| Let's Go 主机 | `--offer`，之后每次交换使用 `--next-offer` | 启动器回复不再继续交换（`pokeldn/lgpe/trade.py`）；玩家退出 |
| Let's Go 加入方 | `--offer`，重复 | 启动器回复不再继续交换；玩家退出 |
| 晶灿钻石／明亮珍珠主机加盟 | `--offer` / `--trade-template`，重复 |再次提供最后一个|
| 传说阿尔宙斯主机并加入 | `--trade-box-record` / `--offer`，重复；方加入将列表交给主机角色 |再次提供最后一个|
| 朱／紫主机并加入 | `--trade-offer`，重复|启动器的交换阶段不再回复任何消息（`pokeldn/sv/trade.py`，`done`）|
| 剑／盾主机并加入 | `--offer-file`，重复；以后的每次交换都会在同一会话中从盒子中运行 |再次提供最后一个|
| 传说 Z-A 主机并加入 | `--trade-offer`，重复；每条新记录在交换开始时都会预览 |最后一个再次提供，新的 PID 为 `--fresh-pid` |

每个交换启动器在每个完成的交换中调用 `pokeldn.ldn.show_done()` 一次，在上面标题表结束的步骤中；它会使开发板的 LED 闪烁并打印 `[done] trade N complete`。会话面板的产品条对该行进行计数，并将前 N 个排队的宝可梦标记为已交易。已接收列表不能代替它：一些启动器在游戏机选择游戏机的宝可梦时，在交换完成之前写入游戏机的宝可梦。

`--fresh-pid` 为每个排队记录提供自己的 PID 和加密常量。 交换 N 以上 1 将收到的内容写入输出路径，扩展名前加上 `-N`（火红／叶绿：`_tradeN_` 和品种；朱／紫：`.N`，按不同提议计算；晶灿钻石／明亮珍珠主机：
`_N`; 传说Z-A和剑／盾：`-N`)。

### 结束运行

当游戏机在交换后离开时，交换运行会自行结束，因此在有效的会话之后，不再需要应用程序的停止。

|角色 |结束于 |
|---|---|
| 主机，每个标题 |游戏机在至少完成一次交换后离开网络（`pokeldn.ldn.left_after_trade`）；游戏机在任何交换可能回来之前就离开，并且主机保持运行 |
| 火红／叶绿 主机 | 火红／叶绿无论交换与否，游戏机已离开网络 |
| 加入 | 加入游戏机主机关闭网络或移交角色（火红／叶绿、Let's Go、剑／盾、晶灿钻石／明亮）； 朱／紫、传说阿尔宙斯和传说 Z-A 再次搜索没有交易的席位，并在交易了的席位后关闭 |

时间限制（`--seconds`，`--hold`）仍然限制着游戏机永不离开的运行。

退出行为的实测结果及待验证问题见各游戏的退出章节。

## 本地文件和发布

跟踪 `config/host.toml` 和运行时参考消息。 `host.local.toml`、密钥、注释、日志、研究图像和生成的构建输出保留在本地。 ROM 校验和比较需要显式
`--sum-reference` 文件。没有生产默认读取 `scratchpad/` 或本地反编译。

设置和准备的提议使用平台的应用程序数据文件夹。 `POKELDN_DATA` 会覆盖它以进行隔离运行。收到的记录使用 `.pk3`、`.pb7`、`.pk8`、`.pb8`、`.pa8`、`.pk9` 或 `.pa9`。

设置通过 `pokeldn.app.storage`（[本地存储](gui.md#local-storage)）公开手动清理。扫描清单可回收文件；删除使用该清单，重新检查当前选择并保留更改的文件。清理会保持应用程序的忙碌状态，因此在删除期间会话和闪烁无法启动。

打包器收集版本管理中的运行时文件、自包含的 PKHeX 可执行文件，以及 ESP32、ESP32-S3、ESP32-C3、ESP32-C6 的合并固件。缺少任何固件镜像都会停止构建；机器配置和笔记不打包。Windows 构建保留子进程日志及停止处理所需的标准输入输出，并隐藏所属控制台；PyInstaller 窗口模式会移除 Windows 上的这些流。Linux 压缩包包含便携可执行文件，不含带构建机器路径的桌面条目。

## 确认

```sh
pip install -r requirements-dev.txt
dotnet build -c Release services/pkhex -warnaserror
python -m pytest tests/ -q -W error -n auto --dist worksteal
```
CI 在 Linux、macOS、Windows 执行这些检查。私人研究测试数据可选；全新检出的仓库无需这些数据，即可测试附带参考数据和共享 PKHeX 服务。

发布版本针对冻结的可执行文件运行 `scripts/check_app.py`：GUI 导入、所有启动器、七种 PKHeX 格式、串行发现和 esptool。该检查不需要钥匙或连接板。
