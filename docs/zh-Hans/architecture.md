# 代码组织

GUI和CLI共享工具预设和宝可梦准备工作。游戏模块保留其测量的线路格式和时序；共享组件属于游戏目录之外。

|地点 |责任|
| --- | --- |
| `pokeldn/app/` |工具目录、参数组装、解析器检查、设置、路径和子节点处理 |
| `pokeldn/pokemon.py` | PKHeX 服务、进口、最终提议验证和收到的文件 |
| `pokeldn/gifts.py` |分享[神秘礼物文件](gifts.md)信封、阅读器、写入器和本机转换|
| `services/pkhex/` |固定 PKHeX.Core 依赖项；合法遭遇生成和游戏兼容性检查|
| `pokeldn/ldn/` |无线收发设备传输、IP、Pia、可靠性和频道表 |
| `pokeldn/gba/` | GBA无线链路协议|
| `pokeldn/gen8.py`，`pokeldn/gen9.py` |共享宝可梦记录编解码器 |
| `pokeldn/<game>/` |游戏身份、消息、状态机和特定于协议的变体 |
| `bin/` |解析器和会话编排|
| `gui/` |视图、小部件、主题和面板控件 |

FRLG 简介、广告和礼品设置位于 `pokeldn/frlg/`。旧的配置和编解码器导入路径保留了小的兼容性垫片。

该应用程序一次运行一个会话，因为一个板服务于一个进程。停止仅出现在会话正在运行的工具上；在另一个工具上启动会停止该会话，等待其退出，然后启动。闪光灯也固定住了电路板，开始等待它。
## 宝可梦准备

共享服务生成合法遭遇并以所选游戏的格式保存导入。每个交换启动器在打开其无线收发设备之前都会准备一个提供的文件。编辑和请求的新身份在应用后进行检查。不兼容的格式、不可用的物种和非法的最终记录将被拒绝。会话的训练家身份不会覆盖导入的宝可梦的初训家。

PKHeX的`LegalityAnalysis.Parsed`记录分析是否完成。助手将其返回为
`parsed`。检查 `parsed: false` 会重新启动帮助器并重复相同的请求一次；第二次不完整的分析会引发验证器错误。已完成的拒绝记录的检查仍被拒绝。服务锁涵盖首次检查、重启和重试。

PID 和加密常数的更改可能会使遭遇相关性失效，尤其是事件和袭击。新身份是可选择加入的，并且必须通过 PKHeX；保留固定事件训练器。所提供的合法记录和新身份下的非法记录保持其自己的 PID 和加密不变，并且启动器会记录 `the offer kept its own PID`。一个构建会在该物种的每一次遭遇之后尝试神秘礼物遭遇，因此具有野生、静态或蛋遭遇的物种永远不会被构建为事件。

构建的宝可梦是将一次遭遇转化为记录。比赛要求光泽度，因此第 3 代 PID 保持 PKHeX 期望的 RNG 相关性。单性别物种从相遇中要求性别：雌性蜂女王或雪妖女仅来自雌性三蜜蜂或雪童子。 PID、IV 以及狂野老虎机的关卡都是随机滚动的，因此一次遭遇在被跳过之前最多可以滚动八次。当没有遇到适合捕获的遭遇时，通过进化遭遇而达到的物种将被提升到其进化水平。当进化物种无性别时，进化记录采用性别（脱壳忍者，来自土居忍士）；当进化物种没有遇到过的形式时，进化记录采用0（Sirfetch'd，来自Galarian Farfetch'd）。

在级别或物种更改后失败的记录会分步修复，每一步都在最后一个之上，并保留第一个合法结果：

1.仅通过HOME（剑／盾中的捷拉奥拉和美录梅塔）到达游戏的活动礼物将获得HOME追踪器。这是在改装之前进行的，改装将取代赛事的固定动作。
2.招式、重新学习招式、TM和TR记录标志、加招式标志、精通标志和传说阿尔宙斯尺寸进行了改装。建议的移动集包含 TM 和 TR 移动，这些移动仅在其记录标记下才合法。
3、进化记录的能力刷新为捕获槽位的进化物种。
4. 没有处理训练家的记录收到第二个记录，`POKELDN`：交换进化已被交易，并且一些礼物（传说Z-A中的玛机雅娜）到达已经处理。
5. 计算某些内容（暴击、受到的伤害、愤怒之拳使用、金币）的进化从该计数开始。
6. 晶灿钻石/明亮珍珠在美丽阈值的进化（美纳斯，170）设定了美丽和它的海雀所暗示的最低光泽。

在改装之前应用能力刷新打破了传说Z-A中的赛富豪，所以顺序是固定的。

PKHeX 无法满足的请求将被拒绝并给出原因。低于最低遭遇级别的级别报告该级别；每次遭遇都被异色锁定的异色请求报告；一个在游戏中没有遭遇过的物种报告了这一点。固定级别的礼物和仅限活动的物种没有较低级别的形式。用六种请求形状（素色、异色、50级、100级、50级异色、昵称）横扫每场游戏的每一个物种，失败的素色构建是：

|游戏 |物种 |失败|
|---|---|---|
| 火红／叶绿 | 386 | 386 0 |
|我们走吧| 153 | 153 0 |
| 传说阿尔宙斯 | 226 | 226 0 |
| 晶灿钻石／明亮珍珠 | 493 | 493 2 |
| 剑／盾 | 664 | 664 3 |
| 传说 Z-A | 364 | 364 5 |
| 朱／紫 | 733 | 733 32 | 32

除了三个之外，每一个失败都是PKHeX在该游戏中没有遇到过的物种：《晶灿钻石／明亮珍珠》中的时拉比和代欧奇希斯，《剑／盾》中的蒂安希、玛机雅娜和美录坦，《传说Z-A》中的粉蝶虫、粉蝶巴基斯坦、彩粉蝶和基格尔德，以及《朱／紫》中只从HOME到达的传奇人物。相遇的三人分别是《传说Z-A》中的美纳斯和《朱／紫》中的诡角鹿和月月熊。 PKHeX赋予诡角鹿和月月熊无9代进化；由丑丑鱼和操控训练家建造的 Z-A 美纳斯停在 PKHeX 进化链中的美纳斯，游戏记录拒绝比赛统计数据。
### 提供选项

构建还可以要求形式、性质、能力、性别、持有的物品、球、最多四个动作、IV 和努力值。移动和形态将遭遇战搜索范围缩小到可以携带它们的遭遇战。性质、能力、性别和 IV 都纳入遭遇标准，因此记录是用它们生成的；搜索第 3 代 PID 以获得所请求的性质。当遭遇掷出其他东西时，记录会按照玩家的方式移动到请求，合法性分析会判断结果：

|不同 |改变 |
|---|---|
|自然 |从第 8 代开始，薄荷糖设定了统计性质 |
|能力|容纳能力的插槽（胶囊或补丁）|
| IV要求31岁|超级训练，级别 100（第 7 代和第 8 代）或 50 级（第 9 代）|
|表格|以玩家改变形态的物种为背景，例如洛托姆的器具 |

持有的物品、球和努力值在构建后设置。超过100的第3代或第4代EV只有在宝可梦自满足以来获得经验后才合法，因此这样的记录将获得一个经验点，低于下一个级别。传说阿尔宙斯的努力水平是存储值加上 IV 的偏差（1 从 20 开始，2 从 26 开始，3 在 31 开始），超过 10 的存储值减去偏差是非法的，因此请求将被视为游戏显示的级别并减去偏差。

记录必须包含每个请求并通过合法性分析。第一次遇到的情况会被保留，而第一个没有遇到的请求会在拒绝中被提及。

提供的选项是一个物种在该游戏中可以拥有的选项：

|选项|上市时间|
|---|---|
|球 | PKHeX 允许它至少在该物种的一次遭遇中 |
|能力|存在携带它的合法构建； 传说Z-A没有列出|
|持有物品 | PKHeX 将其列为游戏已发布的持有物品； Let's Go 和传说阿尔宙斯都没有 |
|努力|电动汽车，每辆 252 辆，总共 510 辆； Let's Go 中的 AV，每张 200 个；传说阿尔宙斯的努力水平，每个 10 |

每场比赛对 25 个物种进行采样，并使用每个列出的球、每种性质、固定的 IV 组、固定的努力值、每种性别和持有的物品来构建每个物种，8095 个构建中的 8088 个是合法的。 PKHeX在剑／盾事件时拉比上拒绝了Hardy、Docile和Bashful，在传说Z-A礼物美录梅塔上也拒绝了同样的三人和Quirky。

在零售剑上，使用自定义选项构建的宝可梦并在下一个排队的交易所进行交易，保存了等于提议的记录（[提议记录](swsh_trade.md#the-offered-record)）。在零售晶灿钻石和朱上，异色37级皮卡丘的昵称、性质、隐藏能力、性别、持有物品、球、四招、IV和努力值在其摘要屏幕上显示每个选项；晶灿钻石的回售记录在所有十二个领域均匹配。
### 决战套装

导入粘贴读取宝可梦 Showdown、Smogon 或 PKHeX 设置与 PKHeX 自己的解析器（`ShowdownParsing.GetShowdownSets`）并填写构建表单；构建然后进行记录。解析器读取 PKHeX 导出的任何语言的集合（英语、法语、德语、意大利语、西班牙语、日语、韩语、中文）； PKHeX 自己的拼写之外的手写标记（例如 `Nature : Rigide` 的 `Nature Rigide`）是它无法读取的行。团队出口
`=== [gen9] Team ===` 标头被跳过。文本遵循 Showdown 的默认值：没有 `Level:` 行意味着级别 100，`IVs:` 行省略的 IV 是 31。解析器按照 PKHeX 的顺序保留统计数据，速度第四。

|集合名称 |结果 |
|---|---|
|解析器无法读取的一行、游戏中不存在的物种或形式、物种缺乏的能力、游戏无法持有的物品、游戏缺乏的动作、EV 超过 510 |拒绝并说明理由；什么都没有填满|
| Tera 类型、Gigantamax、Dynamax 级别、友谊、隐藏力量类型 |没有它，用一张纸条填充|
| Let's Go 中的 EV 或传说中的阿尔宙斯，传说中的 Z-A 能力 |遗漏了，并附有注释|
|几组，在交换队列中|每个交换按其粘贴到的选择器的顺序填充：重复使用后未触及的选择器，否则插入一个交换，直到队列的限制；不适合的集合计入注释。任何一组的拒绝都拒绝粘贴 |
|几套，在队列外|第一个填写表格，并附上注释 |

剑／盾神秘礼物验证WC8封印并使用PKHeX检查支持的物种、形态、招式和安全物品。定制 WC8 卡是发行版，这种结构检查并不会使它们成为正式事件。可选的 `--image` 研究检查使用用户提供的游戏二进制文件；不需要分发卡。
### Let's Go 链接代码

Let's Go 主机的代码是三个插槽。一个插槽打开了游戏机的十个选择器宝可梦，就像游戏机上的两排，五个，作为精灵，其名字在它们下面，因此从未下载的精灵仍然可以读取；镐会填满槽并打开下一个空槽。该值是三个英文名称，以逗号分隔，如 `--code` 所用，Start 会等待，直到所有三个名称都设置完毕：在启动器的默认代码下会出现一个空插槽，而游戏机的搜索永远找不到该代码。
### 交换队列

一个工具，其入口点在一个席位上完成多个交易，最多需要六个宝可梦； “添加交换”添加一个选择器，会话按顺序提供它们，每个已完成的交换一个。选择器成为重复的提议标志：

|工具|优惠为 |最后|之后
|---|---|---|
| 火红／叶绿主机并加入| 队伍文件，`--trades N`，插槽 0 至 N-1 |主机拒绝进一步交换（`PLAYER_CANCEL_TRADE`）并等待玩家的“取消”和“是”；方加入取消离开|
|咱们走吧 主机 | `--offer`，然后每次交换 `--next-offer` |启动器不再应答（`pokeldn/lgpe/trade.py`）；玩家退出 |
|快来加入吧 | `--offer`，重复|发射器不再回答进一步的交换；玩家退出 |
| 晶灿钻石／明亮珍珠主机加盟 | `--offer` / `--trade-template`，重复 |再次提供最后一个|
| 传说阿尔宙斯主机并加入 | `--trade-box-record` / `--offer`，重复；方加入将列表交给主机角色 |再次提供最后一个|
| 朱／紫主机并加入 | `--trade-offer`，重复|启动器的交换阶段不再回复任何消息（`pokeldn/sv/trade.py`，`done`）|
| 剑／盾主机并加入 | `--offer-file`，重复；以后的每次交换都会在同一会话中从盒子中运行 |再次提供最后一个|
| 传说 Z-A 主机并加入 | `--trade-offer`，重复；每条新记录在交换开始时都会预览 |最后一个再次提供，新的 PID 为 `--fresh-pid` |

每个交换启动器在每个完成的交换中调用 `pokeldn.ldn.show_done()` 一次，在上面标题表结束的步骤中；它会使电路板的 LED 闪烁并打印 `[done] trade N complete`。会话面板的产品条对该行进行计数，并将前 N 个排队的宝可梦标记为已交易。已接收列表不能代替它：一些启动器在游戏机选择游戏机的宝可梦时，在交换完成之前写入游戏机的宝可梦。

`--fresh-pid` 为每个排队记录提供自己的 PID 和加密常量。 交换 N 以上 1 将收到的内容写入输出路径，扩展名前加上 `-N`（火红／叶绿：`_tradeN_` 和品种；朱／紫：`.N`，按不同提议计算；晶灿钻石／明亮珍珠主机：
`_N`; 传说Z-A和剑／盾：`-N`)。
### 结束跑步

当游戏机在交换后离开时，交换运行会自行结束，因此在有效的会话之后，不再需要应用程序的停止。

|角色 |结束于 |
|---|---|
| 主机，每个标题 |游戏机在至少完成一次交换后离开网络（`pokeldn.ldn.left_after_trade`）；游戏机在任何交换可能回来之前就离开，并且主机保持运行 |
| 火红／叶绿 主机 | 火红／叶绿无论交换与否，游戏机已离开网络 |
| 加入 | 加入游戏机主机关闭网络或移交角色（火红／叶绿、Let's Go、剑／盾、晶灿钻石／明亮）； 朱／紫、传说阿尔宙斯和传说 Z-A 再次搜索没有交易的席位，并在交易了的席位后关闭 |

时间限制（`--seconds`，`--hold`）仍然限制着游戏机永不离开的运行。

出发测量和开放式问题位于每个标题的出发部分。
## 本地文件和发布

跟踪 `config/host.toml` 和运行时参考消息。 `host.local.toml`、密钥、注释、日志、研究图像和生成的构建输出保留在本地。 ROM 校验和比较需要显式
`--sum-reference` 文件。没有生产默认读取 `scratchpad/` 或本地反编译。

设置和准备的提议使用平台的应用程序数据文件夹。 `POKELDN_DATA` 会覆盖它以进行隔离运行。收到的记录使用 `.pk3`、`.pb7`、`.pk8`、`.pb8`、`.pa8`、`.pk9` 或 `.pa9`。

设置通过 `pokeldn.app.storage`（[本地存储](gui.md#local-storage)）公开手动清理。扫描清单可回收文件；删除使用该清单，重新检查当前选择并保留更改的文件。清理会保持应用程序的忙碌状态，因此在删除期间会话和闪烁无法启动。

加壳器获取跟踪的运行时文件、已发布的独立 PKHeX 可执行文件以及 ESP32、ESP32-S3、ESP32-C3 和 ESP32-C6 的合并无线收发设备固件。任何丢失的图像都会停止构建。它不包括机器配置和注释。 Windows 版本保留子节点进程日志的标准输入和输出并停止处理，并隐藏拥有的游戏机。 PyInstaller 的窗口模式会删除 Windows 上的这些流。 Linux 档案包含可移植的可执行文件；带有构建机器路径的桌面条目被省略。
## 确认

```sh
dotnet build -c Release services/pkhex -warnaserror
python -m pytest tests/ -q -W error
```
 CI 在 Linux、macOS 和 Windows 上运行这些检查。私人研究装置是可选的；干净的结帐测试已发送的参考数据和共享 PKHeX 服务，而无需它们。

发布版本针对冻结的可执行文件运行 `scripts/check_app.py`：GUI 导入、所有启动器、七种 PKHeX 格式、串行发现和 esptool。该检查不需要钥匙或连接板。
